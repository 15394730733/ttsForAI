# Feature Specification: 离线文字转语音工具

**Feature Branch**: `001-offline-tts`
**Created**: 2026-01-23
**Status**: Draft
**Input**: User description: "我想实现一个离线版本的文字转语音工程,要求前端输入要转为语音的文字,然后对生成的语音设置一些基础参数后,就可以生成一个对应mp3格式的音频文件下载下来"

## Clarifications

### Session 2026-01-23

- Q: 部署架构模式是什么? → A: 本地Web服务器模式 - 后端服务运行在本地(如localhost:8000),前端通过HTTP调用本地API
- Q: 使用哪个TTS引擎? → A: edge-tts - 微软Edge浏览器的TTS引擎封装,高质量多音色,完全离线,输出MP3
- Q: 支持哪些语言? → A: 中文为主,支持常见英文 - 中英文混合文本正常朗读,主要音色为中文
- Q: MP3音质标准是什么? → A: 标准质量 (128kbps比特率, 44.1kHz采样率) - 音质与文件大小平衡
- Q: 生成任务如何取消? → A: 允许取消,清理临时文件 - 用户可中止任务,系统清理已生成的部分文件
- Q: 系统是否需要持久化存储生成历史记录? → A: 是 - 保存最近N条生成记录(如最近20条),包括文本、参数、生成时间、文件路径,方便重新下载
- Q: 系统是否需要支持并发处理多个TTS生成任务? → A: 队列模式 - 任务进入队列,后台逐个处理,用户可查看队列状态和取消排队中的任务
- Q: 系统的技术栈版本要求是什么? → A: Python 3.10+ + edge-tts最新稳定版 - 使用主流Python版本,确保长期支持和库兼容性
- Q: 系统需要哪些安全防护措施? → A: 基础防护 - 文本长度验证 + 特殊字符过滤 + 文件路径安全检查,防止路径遍历攻击
- Q: 系统需要哪些日志和监控能力? → A: 基础日志 - 记录错误日志、任务开始/完成/失败事件、关键操作(如文件删除),便于故障排查

### Session 2026-01-24

- Q: 历史记录持久化应该使用哪种存储方案? → A: SQLite数据库 - 使用轻量级数据库,提供结构化查询和更好的数据完整性
- Q: 前端应该使用什么技术栈? → A: Vue.js单页应用 - 使用Vue.js,语法简洁,学习曲线平缓,适合中小型项目
- Q: 生成的音频MP3文件应该存储在哪里? → A: 项目output子目录 - 创建output/或audio/目录在项目根下,集中管理所有生成的音频文件
- Q: 批量文本处理功能(User Story 3)是否需要在MVP阶段实现? → A: 否 - MVP阶段不实现,作为v2.0版本的增强功能,先完成核心单文本转换
- Q: 系统应该提供哪些音色/声音选择? → A: 预设中文音色列表 - 提供3-5个常用中文音色(女声、男声、童声等),覆盖主要场景

## Scope *(mandatory)*

### In Scope (MVP)

- 单文本转语音转换功能(P1)
- 语音参数自定义(语速、音调、音量、音色)(P2)
- 任务队列管理(FIFO处理)
- 生成历史记录(最近20条)
- 基础日志和错误处理
- 前后端分离架构(Vue.js + Python后端)

### Out of Scope (MVP - Planned for v2.0)

- **批量文本处理**: 多段文本同时生成或合并生成(User Story 3, P3)
- **高级音频编辑**: 音频裁剪、拼接、混音等功能
- **云端同步**: 将生成历史同步到云端服务
- **用户账户系统**: 多用户支持、权限管理
- **实时预览**: 生成过程中实时播放预览
- **音频格式转换**: 支持WAV、OGG等其他音频格式

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基础文字转语音 (Priority: P1)

用户输入想要转换为语音的文字内容,选择语音参数,生成MP3格式的音频文件并下载到本地。

**Why this priority**: 这是核心功能,提供了MVP(最小可行产品)所需的所有价值。用户最基本的需求就是将文字转换为语音文件。

**Independent Test**: 用户可以通过输入一段测试文本,选择语音参数,生成并下载音频文件来独立验证此功能。

**Acceptance Scenarios**:

1. **Given** 用户打开了文字转语音页面, **When** 用户在文本框中输入"你好,世界",选择默认语音参数,点击"生成语音"按钮, **Then** 系统在合理时间内生成音频文件,并提供下载链接
2. **Given** 用户已生成音频文件, **When** 用户点击下载按钮, **Then** 浏览器下载一个MP3格式的音频文件到本地
3. **Given** 用户输入了空文本, **When** 用户点击"生成语音"按钮, **Then** 系统显示友好的错误提示,要求输入文本内容

---

### User Story 2 - 语音参数自定义 (Priority: P2)

用户可以调整语音的基础参数(如语速、音调、音量、音色等),以获得更符合需求的语音效果。

**Why this priority**: 参数自定义提升了用户体验和工具的实用性,但不是最核心的功能。用户可以使用默认参数完成基本转换,但自定义参数能满足更多场景需求。

**Independent Test**: 用户可以通过修改单个参数(如仅调整语速)并生成音频,播放后验证参数变化对语音效果的影响。

**Acceptance Scenarios**:

1. **Given** 用户输入了文本, **When** 用户调整语速参数为"1.5倍速",生成并播放音频, **Then** 语音播放速度明显加快但保持清晰
2. **Given** 用户输入了文本, **When** 用户选择不同的音色/声音,生成并播放音频, **Then** 听到不同声音特征的语音
3. **Given** 用户调整了多个参数, **When** 用户点击"重置参数"按钮, **Then** 所有参数恢复到默认值

---

### User Story 3 - 批量文本处理 (Priority: P3) ⚠️ **Out of Scope for MVP**

用户可以一次性输入多段文本,系统为每段文本生成独立的音频文件,或合并为一个音频文件。

**Why this priority**: 批量处理提升了效率,适合需要处理大量文本的场景。但单文本转换已经满足了基本需求,批量处理是增强功能。

**Why Out of Scope**: MVP阶段聚焦核心单文本转换功能,批量处理作为v2.0版本的增强功能实现,以降低初期复杂度并快速交付MVP。

**Independent Test**: 用户可以输入多段文本(如3段),生成后验证是否得到相应数量的音频文件,或一个包含所有内容的合并文件。

**Acceptance Scenarios**:

1. **Given** 用户输入了多段文本(如3段), **When** 用户选择"分别生成"模式并点击生成, **Then** 系统生成3个独立的音频文件,可分别下载
2. **Given** 用户输入了多段文本, **When** 用户选择"合并生成"模式并点击生成, **Then** 系统生成一个包含所有内容的音频文件
3. **Given** 用户正在生成多个音频文件, **When** 生成过程中, **Then** 系统显示进度指示,告知用户当前处理状态

---

### Edge Cases

- What happens when 输入文本超过系统处理上限(如5000字符)? System MUST 显示错误提示并说明字符限制(FR-009)
- How does system handle 生成过程中用户取消操作? System MUST 允许取消任务并清理临时文件(FR-014)
- What happens when 浏览器不支持某些音频格式? System MUST 提供MP3格式作为标准输出,广泛兼容
- How does system handle 用户快速连续点击"生成"按钮? System MUST 防止重复提交,将任务加入队列
- What happens when 文本包含特殊字符或不支持的符号? System MUST 过滤或转义特殊字符,或提供友好错误提示
- How does system handle 生成失败或超时的情况? System MUST 显示具体错误信息和解决建议(FR-011)
- What happens when 队列中已有多个任务,用户尝试取消正在处理的任务? System MUST 仅允许取消排队中的任务,正在处理的任务需等待完成或失败
- How does system handle 队列满载(如达到最大限制)? System MUST 设定合理的队列上限(如10个任务),超过时显示队列繁忙提示
- What happens when 输入文本包含路径遍历字符(如../../etc/passwd)? System MUST 识别并过滤这些字符,拒绝处理并显示安全提示(FR-024)
- What happens when 用户尝试通过自定义文件名参数访问系统目录? System MUST 验证文件路径,确保所有操作限制在指定的输出目录内(FR-025)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 允许用户在文本输入框中输入或粘贴要转换的文字内容
- **FR-002**: System MUST 提供文本长度计数和上限提示(默认上限5000字符)
- **FR-003**: System MUST 提供语音参数设置界面,包括但不限于:语速、音调、音量、音色/声音选择
- **FR-004**: System MUST 为每个参数提供合理的默认值和可选范围
- **FR-036**: System MUST 提供预设的中文音色列表,至少包括:女声(默认)、男声、童声3种基础音色
- **FR-037**: System MUST 在音色选择器中显示音色名称和示例(如"晓晓-女声"),提升用户体验
- **FR-005**: System MUST 在用户点击"生成"后,使用edge-tts引擎将文本转换为语音并生成MP3格式音频文件(128kbps比特率, 44.1kHz采样率)
- **FR-006**: System MUST 提供音频文件下载功能,文件名格式为"语音_[日期时间].mp3"或用户自定义名称
- **FR-007**: System MUST 在生成过程中显示进度提示和加载状态
- **FR-008**: System MUST 验证输入文本不为空,否则显示友好错误提示
- **FR-009**: System MUST 处理文本长度超限情况,显示清晰的错误信息和字符限制
- **FR-010**: System MUST 提供参数重置功能,一键恢复所有参数到默认值
- **FR-011**: System MUST 在生成失败时显示具体的错误信息和建议
- **FR-012**: System MUST 支持离线运行,后端服务部署在本地(localhost),不依赖在线TTS服务或外部API调用
- **FR-013**: System MUST 支持中文文本朗读为主,并支持常见英文内容(中英文混合文本正常朗读)
- **FR-014**: System MUST 允许用户在生成过程中取消任务,并清理已生成的临时文件
- **FR-015**: System MUST 保存最近20条生成历史记录,包括:输入文本摘要(前100字符)、语音参数、生成时间、文件路径、文件大小
- **FR-016**: System MUST 在界面上提供历史记录列表,允许用户查看详情和重新下载历史音频文件
- **FR-017**: System MUST 自动清理超过20条的历史记录,采用FIFO(先进先出)策略
- **FR-018**: System MUST 允许用户手动删除单条或全部历史记录
- **FR-019**: System MUST 实现任务队列机制,所有生成任务按提交顺序进入队列并逐个处理
- **FR-020**: System MUST 在界面上显示当前队列状态,包括:排队中任务数量、正在处理的任务、已完成任务
- **FR-021**: System MUST 允许用户取消队列中等待的任务(尚未开始处理的任务),立即从队列移除
- **FR-022**: System MUST 为每个任务提供唯一任务ID,用于追踪任务状态和在历史记录中关联
- **FR-023**: System MUST 验证所有输入文本的长度不超过5000字符(FR-009的具体实现)
- **FR-024**: System MUST 过滤输入文本中的潜在恶意字符序列(如控制字符、路径遍历模式 ../)
- **FR-025**: System MUST 验证和sanitize所有文件路径参数,防止路径遍历攻击,确保文件操作限制在指定目录内
- **FR-026**: System MUST 对用户输入进行转义处理,防止命令注入风险
- **FR-027**: System MUST 记录所有错误日志,包括错误类型、错误信息、时间戳、相关任务ID
- **FR-028**: System MUST 记录任务生命周期事件:任务创建(进入队列)、任务开始处理、任务完成、任务失败、任务取消
- **FR-029**: System MUST 记录关键操作:历史记录删除(单条/全部)、临时文件清理、队列状态变更
- **FR-030**: System MUST 将日志输出到文件(默认logs目录),日志文件按日期滚动(每天一个文件)
- **FR-031**: System MUST 在日志中包含足够的上下文信息,便于故障排查和问题定位
- **FR-032**: System MUST 将生成的音频文件存储在项目根目录的output/子目录下
- **FR-033**: System MUST 在应用启动时自动创建output/目录(如果不存在)
- **FR-034**: System MUST 为每个生成的音频文件提供唯一文件名,格式为"tts_[任务ID]_[时间戳].mp3"
- **FR-035**: System MUST 在历史记录删除时同步删除对应的音频文件(可选保留文件)

### Technical Constraints

- **TC-001**: 后端服务MUST使用Python 3.10或更高版本运行
- **TC-002**: 系统MUST使用edge-tts最新稳定版本作为TTS引擎(通过pip安装)
- **TC-003**: 后端服务MUST部署为本地Web服务器(如使用Flask或FastAPI框架),监听localhost端口(默认8000)
- **TC-004**: 系统MUST提供RESTful API接口,前端通过HTTP调用后端服务
- **TC-005**: 历史记录存储MUST使用SQLite数据库,数据库文件位于项目根目录的data/tts_history.db
- **TC-006**: 系统MUST在Windows/Linux/macOS平台上兼容运行
- **TC-007**: System MUST在应用启动时自动初始化SQLite数据库和创建必要的表结构(如果不存在)
- **TC-008**: 前端MUST使用Vue.js 3.x版本构建单页应用(SPA)
- **TC-009**: 前端MUST提供静态文件服务,由后端Web服务器托管,或使用开发服务器(如Vite)

### Key Entities

- **文本输入(Text Input)**: 用户输入的要转换为语音的文字内容,包含文本内容和长度属性
- **语音参数(Voice Parameters)**: 控制语音效果的设置集合,包括语速(0.5-2.0倍)、音调(低/中/高或Hz值)、音量(0-100%)、音色/声音(预设列表,至少包含女声、男声、童声三种,使用edge-tts音色名称如"zh-CN-XiaoxiaoNeural")
- **音频文件(Audio File)**: 生成的MP3格式语音文件,包含文件名、二进制数据、文件大小、时长、比特率(128kbps)、采样率(44.1kHz)等属性
- **生成任务(Generation Task)**: 一次文本转语音的处理过程,包含任务ID(唯一标识符)、输入文本、参数设置、状态(排队中/处理中/成功/失败/已取消)、进度百分比、结果文件路径或错误信息、提交时间戳
- **任务队列(Task Queue)**: 待处理的生成任务集合,按FIFO顺序管理,包含队列长度、当前处理任务的索引、队列中的任务列表
- **生成历史记录(Generation History)**: 历史生成任务的持久化记录,存储在SQLite数据库中,包含:记录ID(主键,自增)、任务ID(唯一标识符,外键关联)、文本摘要(前100字符)、语音参数快照(JSON格式)、生成时间戳、文件存储路径、文件大小、任务状态,最多保存20条

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在30秒内完成从输入文本到下载音频文件的全过程(文本长度<500字符时)
- **SC-002**: 系统支持至少3种不同的音色/声音选择
- **SC-003**: 语音参数调整后,用户能明显感知到语音效果的变化(如语速、音调)
- **SC-004**: 系统在处理标准长度文本(500字符)时,生成时间不超过10秒
- **SC-005**: 生成的音频文件质量达到可接受标准,无明显的卡顿、噪音或失真
- **SC-006**: 95%的用户能够在首次使用时成功生成并下载音频文件,无需查看帮助文档
- **SC-007**: 系统能够处理最大5000字符的文本而不崩溃或出现未处理的错误
